# Отчёт по рефакторингу ЭЛОУ-АВТ MVP

## Результат

Текущий функционал сохранён, включая быстрый вход кнопками для демонстрации
КТК. Физический движок не изменялся. Основная переработка затронула загрузку
3D-экрана полевого оператора, API, авторизацию, работу со схемами и жизненный
цикл приложения.

## 3D-экран полевого оператора

- фон iframe, WebGL-сцены и индикатора загрузки сделан белым;
- исправлена гонка загрузки Three.js (`defer` вместо небезопасного `async`);
- добавлены явные события готовности/ошибки и кнопка повторной загрузки;
- смена темы больше не перезагружает тяжёлую сцену;
- геометрии примитивов кэшируются, материалы переиспользуются;
- трубы, опоры и кабельные трассы объединены в `InstancedMesh`-пакеты;
- A* использует повторно выделенные typed arrays, числовую heap и кэш маршрутов;
- отрисовка ограничена 30 FPS и останавливается в скрытой вкладке;
- pixel ratio ограничен 1.5, включён `high-performance` WebGL;
- hover-raycast выполняется не чаще одного раза за кадр;
- устранено глобальное окрашивание оборудования при выборе объекта;
- вывод полевых дефектов переведён с динамического HTML на `textContent`.

CPU-only benchmark строит реальную сцену на Three.js, но заменяет WebGL-рендерер
заглушкой. Медиана трёх отдельных запусков:

| Метрика | До | После | Изменение |
|---|---:|---:|---:|
| Подготовка сцены | 1081,1 мс | 247,7 мс | в 4,4 раза быстрее |
| Heap delta | 80,3 МБ | 23,0 МБ | −71% |
| Объекты сцены | 12 379 | 7 380 | −40% |
| Уникальные геометрии | 11 921 | 405 | −96,6% |
| Уникальные материалы | 1 460 | 78 | −94,7% |

Браузерное время зависит от GPU и компьютера стенда, поэтому benchmark не
равен пользовательскому времени загрузки. Однако он измеряет ту же подготовку
маршрутов и сцены, а сокращение GPU-ресурсов и draw calls дополнительно помогает
в реальном браузере.

## Схемы и дублирующиеся ID

- ни одна схема, узел или связь не удалены;
- формат схем повышен до `1.2`;
- повторные ID узлов/связей получают стабильный суффикс `__dupN`;
- неоднозначные старые связи остаются привязаны к первому объекту;
- исправлена внутренняя идентичность копий схем: сохранение больше не может
  случайно перезаписать `default.json`;
- запись схем и маркера последней схемы атомарная;
- имя схемы проверяется, выход из каталога `schemes/` запрещён;
- миграция проверена на повторный запуск: результат идемпотентен.

После миграции сохранено 1038 узлов и 1382 связи во всех десяти файлах схем.

## Стабильность и производительность приложения

- страницы React переведены на route-level lazy loading;
- тяжёлые React Flow и ECharts вынесены в отдельные chunks;
- API-запросы получили таймаут, ограниченный текст ошибки и понятное сообщение;
- WebSocket reconnect получил backoff и корректную остановку при unmount/401/403;
- фоновый поток симуляции запускается и завершается через lifespan FastAPI;
- исключён двойной DigitalTwin при прямом запуске `api_server.py`;
- ID тренировочной сессии защищён от коллизий;
- polling 3D-экрана приостанавливается в скрытой вкладке.

## Безопасность

- авторизация включена по умолчанию;
- универсальный секрет удалён: локально создаётся уникальный секрет, production
  требует `ELOU_AUTH_SECRET`;
- wildcard CORS с credentials заменён allowlist;
- добавлены HTTP security headers;
- действия записываются от аутентифицированного пользователя, а не от
  `operator_id` из тела запроса;
- назначать другого оператора на сессию могут только пользователи с правом
  мониторинга;
- WebSocket-токен текущего клиента передаётся не в URL, а в subprotocol;
- добавлена проверка WebSocket permissions;
- вход ограничен пятью неудачными попытками в минуту для пары IP/логин;
- Pydantic-модели используют безопасные `default_factory` и ограничения длины;
- токены проверяются по времени, subject, длине и уникальному `jti`.
- ECharts обновлён с уязвимой ветки 5.x до исправленной 6.1.0; production audit
  npm не находит известных уязвимостей.

Демо-пароли намеренно оставлены равными логинам, а быстрые кнопки входа —
активными, согласно назначению MVP. Это осознанное исключение, не production
настройка.

## Проверки

- production-сборка фронтенда: успешно (844 модуля);
- `npm audit --omit=dev --audit-level=moderate`: 0 уязвимостей;
- синтаксис встроенного JavaScript 3D-модели: успешно;
- `compileall` Python: успешно;
- быстрый вход для всех четырёх demo-аккаунтов, проверка токена и RBAC: успешно;
- 30 шагов демонстрации физического ядра: успешно;
- все файлы схем: уникальные node/edge ID, корректные counts, повторная миграция
  не меняет результат;
- benchmark 3D: три запуска до и после, значения приведены выше.

Полный pytest не запускался в среде рефакторинга: в ней отсутствовали FastAPI и
pytest, а установка Python-пакетов была недоступна. Тесты обновлены под новый
безопасный режим авторизации; команды запуска указаны в `README.md`.

## Точки роста физического движка (код не менялся)

1. Ввести golden-наборы режимов и проверять материальный/энергетический баланс
   на каждом шаге с заданными допусками.
2. Профилировать MESH и гидравлику, отделить неизменяемую матрицу/топологию от
   шага решателя и переиспользовать факторизации.
3. Добавить контроль сходимости: максимум итераций, невязки, fallback последнего
   корректного состояния и явный статус `non-converged`.
4. Ввести property-based тесты физических границ, единиц измерения и сохранения
   массы/энергии на широких диапазонах входов.
5. Валидировать термодинамику на паспортных/лабораторных данных; для промышленной
   точности рассмотреть Peng–Robinson и калибровку бинарных коэффициентов.
6. Разделить realtime-оркестрацию и вычислительный worker, чтобы тяжёлый solve не
   блокировал API/WebSocket, сохраняя фиксированный физический timestep.
7. Добавить детерминированные checkpoint/replay тесты сценариев и версионирование
   параметров расчётного ядра.
